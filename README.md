# Booking Site — онлайн-бронирование для сферы услуг

Полноценный сайт бронирования для PS-клубов, барбершопов, бильярдных.
Клиентская часть — только клики (карточки услуг/мастеров + интерактивный
календарь, без ручного ввода дат). Админ-панель — расписание на день и
вкладка аналитики с графиками. Backend на FastAPI + SQLite, фронтенд на
React (Vite) + Tailwind CSS.

## Структура проекта

    ├── index.html
    ├── package.json
    ├── vite.config.js
    ├── tailwind.config.js
    ├── postcss.config.js
    └── src/
        ├── main.jsx
        ├── App.jsx              # переключатель Клиент / Админ-панель
        ├── api.js                # обёртка над fetch
        ├── dateUtils.js           # работа с локальной датой (без бага часового пояса)

## Backend — запуск

```bash
cd backend
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

При первом запуске автоматически создастся `booking.db` (SQLite) и засеются
демо-ресурсы: 3× PS5, 2× бильярдный стол, 2× барбера.

- API: `http://localhost:8000`
- Swagger: `http://localhost:8000/docs`

### Эндпоинты

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/resources` | список всех ресурсов |
| GET | `/api/bookings?date=YYYY-MM-DD` | брони на дату |
| POST | `/api/bookings` | создать бронь (проверяет наложение времени) |
| PATCH | `/api/bookings/{id}/status` | изменить статус брони |
| GET | `/api/stats/overview?date_from=&date_to=` | статистика: брони, выручка, популярные ресурсы/слоты |

## Frontend — запуск

```bash
cd frontend
npm install
npm run dev
```

Приложение будет доступно на `http://localhost:5173`.

### ⚠️ Важно: адрес backend в `frontend/.env`

```
VITE_API_URL=https://booking-mvp-up3b.onrender.com
```

Я поставил по умолчанию адрес backend, который вы упоминали ранее для бота
(`booking-mvp-up3b.onrender.com`) — **в предположении, что это тот же самый
backend из этого проекта**, уже задеплоенный на Render. Если это так —
сайт заработает сразу после `npm install && npm run dev`, без запуска
backend локально.

**Но в этом проекте backend изменился** — добавился новый эндпоинт
`/api/stats/overview` для аналитики. Если Render разворачивает backend
автоматически из вашего репозитория — обновите там код backend (замените
на файлы из `backend/` этого архива) и передеплойте, иначе вкладка
«Аналитика» в админке будет получать ошибку 404.

Если хотите проверить всё сначала локально — смените в `.env`:
```
VITE_API_URL=http://localhost:8000
```
и запустите backend локально (см. выше).

## Клиентский сценарий — «кликай и бронируй»

1. Клик по категории (PS5 / Бильярд / Барбер) — карточка
2. Клик по конкретному ресурсу (стол/приставка/мастер) — карточка
3. Клик по дате в интерактивном календаре — месяц, стрелки вперёд/назад,
   прошедшие дни неактивны, сегодняшний день подсвечен. Дата всегда
   считается от реального текущего дня устройства пользователя
   (без UTC-сдвига — см. `dateUtils.js`)
4. Клик по свободному времени (занятые слоты серые и недоступны)
5. Имя и телефон — единственные текстовые поля, они нужны, чтобы с
   клиентом можно было связаться для подтверждения брони
6. Кнопка «Забронировать» → плашка «Бронь принята!»

## Админ-панель

**Вкладка «Расписание»**: сетка ресурс × время на выбранный день (дата тоже
выбирается кликом по календарю), фильтр по ресурсу, ручное добавление брони,
подтверждение/отмена прямо в ячейке, выручка за день.

**Вкладка «Аналитика»**: переключатель периода (7 дней / 30 дней / всё
время), KPI-карточки (всего броней, выручка, ожидают, отменено), график
выручки по дням, топ популярных ресурсов и топ популярного времени —
всё обновляется при каждом открытии вкладки/смене периода.
